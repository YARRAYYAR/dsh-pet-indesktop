## 一、总体评价

这个项目的**核心工程质量明显高于同类个人项目**：

- 分层清晰：`catalog`（事实来源）/ `library`（媒体索引）/ `webm_clip`（解码）/ `window`（状态机）/ `config`（持久化）职责分明；

- README 里的「开发经验与教训」章节本身就是高质量文档。

真正需要修缮的不是“代码写得好不好”，而是三类问题：

1. **一次合并（7d18242）疑似丢失了 AI 聊天功能的集成胶水**，留下约 1800 行“半接入”代码和 1 个必崩的打包入口；
2. **CI 与测试配置和仓库现状脱节**（只跑 4/8 个测试文件、无 Windows CI）；
3. **文档漂移**（README 933 行中约 290 行是内嵌的旧版全文、`注意事项.txt` 数字过期、缺 LICENSE 文件）。

## 二、问题清单（按优先级）

### P0-1　AI 聊天子系统处于“半接入”状态（合并丢失集成胶水）

**现象**：`pet/chat/`（约 1600 行：models / providers / prompt / service / session_store / settings_dialog / widgets / pet_link / styles.qss）和 `pet/speech_bubble.py` 完整存在，`tests/test_chat_subsystem.py`（555 行）也存在，但它们**与主程序之间的胶水全部缺失**：

| 缺失的胶水 | 证据 | 后果 |
|---|---|---|
| `Config.chat_settings()` / `set_chat_settings()` / `resolve_api_key()` | `pet/chat/widgets.py:263`、`:758`、`:807`，`pet/chat/settings_dialog.py:5` 直接调用；`pet/config.py` 中无这些方法 | `ChatWindow` / `ChatSettingsDialog` 一实例化即 `AttributeError` |
| `PetWindow.visible_content_rect()` 与 `_squash_geometry()` | `tests/test_chat_subsystem.py:17` `from pet.window import _squash_geometry`；`pet/window.py` 中不存在 | 该测试文件**收集阶段即 ImportError** |
| 打开聊天窗口的菜单入口 | `pet/app.py`、`pet/window.py` 中 grep 不到任何 `chat` 引用 | 功能对用户完全不可达（死代码） |
| 配置版本 3 迁移 | `tests/test_chat_subsystem.py:115` 断言保存后 `version == 3`；`pet/config.py` 当前为 `version: 2` | 测试期望与实现不一致 |

**旁证**：`docs/grill-2026-08-21-ai-chat.md` 记录了完整需求（`codex/ai-chat` 分支）；`docs/BUILD_ARTIFACTS-2026-08-22.md:34` 记录当时 `pytest -q` **26 passed**（当前仓库最多只能收集到 16 个非 chat 用例）——说明聊天功能曾在别的分支/目录完整跑通过，合并进 `main` 时只带回了模块本体，没带回 `config.py` / `window.py` / `app.py` 侧的接线。

**修复建议（二选一）**：

- **方案 A（恢复功能，推荐）**：按 `docs/grill-2026-08-21-ai-chat.md` 的决策补回胶水——
  1. `Config` 增加 `chat_settings()` / `set_chat_settings()` / `resolve_api_key()`，并把 `version` 升到 3，按测试期望做旧字段（`chat_api_url` / `chat_api_key` / `chat_model` / `chat_system_prompt`）迁移；
  2. `pet/window.py` 恢复 `_squash_geometry()` 与 `visible_content_rect()`（测试对两者行为有明确断言，可直接照测试写实现）；
  3. `main()` 恢复 `enable_chat` 参数（见 P0-2），在托盘/右键菜单加「AI 对话」入口；
  4. 把 `tests/test_chat_subsystem.py` 加回 CI 的 pytest 列表。
- **方案 B（裁剪）**：若决定不再要聊天功能，删除 `pet/chat/`、`pet/speech_bubble.py`、`tests/test_chat_subsystem.py`、`packaging/pet_entry_no_chat.py`，并同步更新 `requirements.txt`（`keyring` 仅聊天用到）与 README。

> 不建议保持现状：半接入代码会持续产生“测试跑了才发现坏”的维护噪音，也会误导后续贡献者。

### P0-2　`packaging/pet_entry_no_chat.py` 打包入口必然崩溃

`packaging/pet_entry_no_chat.py:10` 调用 `main(enable_chat=False)`，但 `pet/app.py` 的实际签名是 `def main(argv: list[str] | None = None) -> int` —— 没有 `enable_chat` 参数。任何用该入口打包的“无聊天版”exe **启动即 `TypeError`**。

**修复**：随 P0-1 方案 A 恢复参数；或（方案 B 下）直接删除该入口文件。

### P1-3　CI 只跑 4/8 个测试文件，坏测试被静默绕过

`.github/workflows/build-macos.yml:38` 只运行：

```
pytest tests/test_alpha_resampling.py tests/test_media_runtime.py tests/test_runtime.py tests/test_stability.py -q
```

- `tests/test_runtime_cleanup.py`、`tests/test_harness_launcher.py` **能通过却没有跑**（本机已验证）；
- `tests/test_chat_subsystem.py` 因 P0-1 失败而被排除，但 workflow 里**没有任何注释说明原因**——这正是“合并丢胶水”没人发现的原因。

**修复**：改为 `python -m pytest tests -q`（先按 P0-1 修复 chat 测试），或至少把能过的补进去，并用 `# TODO(P0-1)` 注释标注排除项；给 `tests/` 加一个 `pytest.ini`/`pyproject.toml` 固化 offscreen 平台参数。

### P1-4　没有 Windows CI

Windows（exe onefile）是 README 里的主要发布目标，但仓库只有 `build-macos.yml`；Windows 侧的打包命令全靠人工在本机执行（README「打包为 exe」），P0-2 这类入口崩溃就是人工流程漏掉的。

**修复**：新增 `build-windows.yml`（`windows-latest`）：`compileall` + `pytest`（`QT_QPA_PLATFORM=offscreen`）+ PyInstaller onefile 打包 webm/gif 两个变体 + `--selftest` 冒烟 + 上传 artifact。一次性投入约半天，之后每次 push 自动兜底。

### P2-6　`注意事项.txt` 与 README 大段重复且已过期
